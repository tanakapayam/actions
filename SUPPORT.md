# Getting help

- **Using the actions:** start with the [guide](docs/guide.md), then [what each message means](docs/failures.md) and the [FAQ](docs/faq.md). Most problems are one of the rows in those.
- **A bug, or something the docs get wrong:** open an issue using the *Bug report* form. It asks for the things that make a problem reproducible: the pinned release, your workflow step and the log.
- **An idea:** open an issue using the *Feature request* form. A concrete problem you hit is the best starting point; "support for X" is easier to act on with the registry's API in hand.
- **A security problem:** please do not open an issue. See [SECURITY.md](SECURITY.md).

This is a small project maintained by one person, so replies may take a few days. A reproduction that works from a fresh repository, even a tiny one, is the fastest way to a fix.
